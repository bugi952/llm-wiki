# Natural Language to SQL (NL2SQL)

## 정의


## 주요 발전
- **2026-04-22**: CLARITY 프레임워크: 제약 기반 파이프라인으로 대화형 다면적 모호성 벤치마크 자동생성 [(원문)](https://arxiv.org/abs/2604.22313)
- **2026-04-24**: SQLyzr 플랫폼이 workload alignment와 database scaling을 통한 realistic evaluation 제공 [(원문)](https://arxiv.org/abs/2604.21214)
- **2026-04-24**: SemanticAgent: 분석-합성-검증 3단계로 의미론적 유효성 보장하는 데이터 합성 프레임워크 [(원문)](https://arxiv.org/abs/2604.21414)
- **2026-04-21**: 다중 테이블 entity matching에서 LLM의 언어 이해 능력으로 의미 불일치 해결 [(원문)](https://arxiv.org/abs/2604.21238)
- **2025-10-12**: MTSQL-R1: 다중 턴 SQL을 MDP로 재정의, 실행→검증→개선 반복 사이클 [(원문)](https://arxiv.org/abs/2510.12831)
- **2026-04-21**: Table Question Answering은 표형식 데이터에 대한 자연어 질문 응답으로 테이블 표현, 질문 복잡도, 모달리티, 도메인 다양성 포함 [(원문)](https://arxiv.org/abs/2510.09671)
- **2026-04-16**: 자가 치유 LLM 파이프라인: 자동 스키마 인트로스펙션 + SQLSTATE 기반 에러 진단 + 반복 복구 [(원문)](https://arxiv.org/abs/2604.16511)
- **2026-04-21**: NL2SQLBench: 모듈별 벤치마킹 (Schema Selection, Candidate Generation, Query Revision) [(원문)](https://arxiv.org/abs/2604.16493)
- **2026-04-21**: 단순 커리큘럼 학습(복잡도순 정렬)은 catastrophic forgetting으로 표준 fine-tuning을 초과 불가. nested joins와 복잡한 스키마에서 여전히 어려움 [(원문)](https://arxiv.org/abs/2604.18254)
- **2026-04-17**: PV-SQL: Probe-Verify 이원화로 데이터 값 형식, 컬럼 의미, 테이블 관계 모호성 해결하여 BIRD 벤치마크 정확도 5% 향상 [(원문)](https://arxiv.org/abs/2604.17653)
- **2026-04-21**: 자연어 최적화 문제 설명을 형식화된 OR 모델로 자동 변환 (synthetic data + solver feedback RL) [(원문)](https://arxiv.org/abs/2604.16804)
