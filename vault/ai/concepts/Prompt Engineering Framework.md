# Prompt Engineering Framework

## 정의


## 주요 발전
- **2026-04-27**: LLM의 프롬프트 성능 변동은 동일 작업의 여러 어텐션 헤드 활성화 방식의 차이로 설명 가능하며, 작업 특화 헤드가 이후 답변 생성을 촉발 [(원문)](https://arxiv.org/abs/2604.22027)
- **2026-04-21**: 학습 가능한 prompt generator의 RL 최적화로 대상 지식 억제와 일반 능력 보존의 균형 [(원문)](https://arxiv.org/abs/2604.21251)
- **2026-04-21**: COMPASS: 사용자의 인지 상태(주의도, 이해도, 불확실성)를 POMDP로 모델링한 자적응 프롬프트 합성 방법 [(원문)](https://arxiv.org/abs/2604.21092)
- **2026-04-22**: SAIR Equational Theories 문제에서 40+ 프롬프트 변형 5주 테스트 결과 성능 포화점 60-79% 확인. 수학적 결정 불가능성이 근본 원인 [(원문)](https://arxiv.org/abs/2604.18897)
- **2026-04-22**: GROVE: 단일 출력 기반 상호작용에서 분포 기반 프롬프트 최적화로 전환, 텍스트 그래프로 공유 구조 가시화 [(원문)](https://arxiv.org/abs/2604.18724)
- **2026-04-21**: 베이지안 추론으로 프롬프트 불확실성 정량화 (arXiv:2506.10060) [(원문)](https://arxiv.org/abs/2506.10060)
- **2025-05-14**: PRL (RL 기반 프롬프트)은 텍스트 분류에서 APE 대비 +2.58%, EvoPrompt 대비 +1.00% 개선 달성 (arXiv:2505.14412) [(원문)](https://arxiv.org/abs/2505.14412)
- **2025-04**: TextTIGER는 프롬프트의 엔티티에 대해 외부 정보로 확장한 후 LLM으로 요약하여 과도한 입력 길이 문제 해결하며, 캡션·이미지·상세 설명·엔티티 리스트를 포함한 새 데이셋 구성 [(원문)](https://arxiv.org/abs/2504.18269)
- **2026-04-21**: Chain-of-Thought와 self-debate는 SE 편향 완화에 부분적 효과만 제공 [(원문)](https://arxiv.org/abs/2604.16756)
- **2026-04-21**: 해석적 작업에서는 높은 확률적 변동, 지식 기반 작업에서는 안정적 → 다중 프롬프트 투표로 재현성 향상 가능 [(원문)](https://arxiv.org/abs/2604.16413)
- **2026-04-21**: Taylor 전개로 유도한 prompt 민감도의 상한이 과도히 높음, 안정성 개선의 이론적 근거 제시 (arXiv 2604.18389) [(원문)](https://arxiv.org/abs/2604.18389)
- **2026-04-21**: Least-to-Most (LTM) 및 Active Prompting 전략이 약학역학 코딩 작업에서 relevance/logic 점수 향상 [(원문)](https://arxiv.org/abs/2604.17988)
- **2026-04-21**: ContraPrompt는 성공/재시도 사이의 완전한 중간 추론 과정 비교(dyadic analysis)를 통해 기존 방법이 포착하지 못한 최적화 신호 추출 (2026-04-21) [(원문)](https://arxiv.org/abs/2604.17937)
- **2026-04-21**: Semantic Density Effect (SDE): 저정보 토큰 제거로 의미밀도 증가 시 모든 주요 LLM에서 정확도 +8.4% 향상 (5개 모델, 7개 벤치마크 검증) [(원문)](https://arxiv.org/abs/2604.17659)
- **2026-04-20**: PieceHint: 문제 난이도별 추론 단계 중요도 분석, 선택적 힌트 주입 및 점진적 철회 [(원문)](https://arxiv.org/abs/2604.15830)
